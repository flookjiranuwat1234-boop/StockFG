# ระบบคลังสินค้า (Node.js + PostgreSQL)

เว็บคลังสินค้าสำหรับผู้ใช้ไม่เกิน ~10 คน ข้อมูลเก็บใน PostgreSQL ใช้ร่วมกันหลายเครื่อง มีบทบาท Super admin สำหรับจัดการบัญชี และบันทึกว่าใครทำรายการรับ/เบิก

## โครงสร้าง
- `server.js` เซิร์ฟเวอร์ API (Express) + เสิร์ฟหน้าเว็บ
- `db.js` เชื่อมฐานข้อมูล + สร้างตารางอัตโนมัติเมื่อเริ่มระบบ
- `public/index.html` หน้าเว็บ (ไฟล์เดียว ฝังไลบรารี QR/Excel ไว้แล้ว)
- `scripts/add-user.js` เพิ่มผู้ใช้ / เปลี่ยนรหัสผ่าน

## ตัวแปรที่ต้องตั้ง (Environment Variables)
| ชื่อ | ความหมาย |
|---|---|
| `DATABASE_URL` | ลิงก์เชื่อมต่อ PostgreSQL (Railway/Render/Supabase ให้มา) |
| `JWT_SECRET` | ข้อความสุ่มยาว 24 ตัวอักษรขึ้นไป ห้ามเปิดเผย |
| `ADMIN_USER`, `ADMIN_PASS`, `ADMIN_NAME` | สร้าง Super admin คนแรกอัตโนมัติ (ใช้ตอนตารางผู้ใช้ยังว่างเท่านั้น; รหัสผ่านอย่างน้อย 12 ตัวอักษร) |
| `NODE_ENV=production` | เปิดโหมดใช้งานจริง (คุกกี้ล็อกอินเป็น secure) |

## นำขึ้นคลาวด์ (เลือกอย่างใดอย่างหนึ่ง)
**Railway** (ง่ายสุด): สร้างโปรเจกต์ > Deploy from GitHub (หรืออัปโหลดโค้ด) > เพิ่ม PostgreSQL > ในบริการเว็บตั้ง `DATABASE_URL` = ค่า `DATABASE_URL` ของ Postgres (reference variable) แล้วตั้งตัวแปรที่เหลือ > Start command: `npm start`

**Render**: New Web Service (Build: `npm install`, Start: `npm start`) + New PostgreSQL แล้วใส่ Internal Database URL ใน `DATABASE_URL`

**Supabase**: ใช้เป็นฐานข้อมูลเท่านั้น (ใช้ Connection string แบบ Session pooler หรือ Direct) ส่วนตัวเว็บยังต้องรันบน Railway/Render

> **ติดตั้งใหม่**: หากตั้ง `ADMIN_USER/ADMIN_PASS` ระบบจะสร้าง Super admin คนแรกให้อัตโนมัติ; หากใช้คำสั่ง CLI สร้างบัญชีแรก บัญชีนั้นจะเป็น Super admin ด้วย
>
> **ฐานข้อมูลเดิม**: หลัง deploy รุ่นนี้ บัญชีเดิมจะเป็นผู้ใช้ทั่วไปโดยค่าเริ่มต้น ให้ผู้ดูแลระบบที่ได้รับอนุญาตเลื่อนบัญชีที่มีอยู่เป็น Super admin หนึ่งบัญชี เช่น `npm run add-user -- --promote admin` (แทน `admin` ด้วยชื่อบัญชีจริง ห้ามพิมพ์เครื่องหมาย `< >`) จากนั้นรีเฟรชหน้าเว็บเพื่อแสดงปุ่มจัดการบัญชี
>
> เพิ่มผู้ใช้หรือเปลี่ยนรหัสผ่านผ่าน CLI ได้ด้วย `npm run add-user -- USERNAME PASSWORD "DISPLAY NAME"` โดยแทนคำตัวใหญ่ด้วยข้อมูลจริง; รหัสผ่านต้องมีอย่างน้อย 12 ตัวและไม่ควรซ้ำกับบริการอื่น

## รันในเครื่อง
```
npm install
cp .env.example .env   # แก้ค่าใน .env แล้ว export เข้า shell หรือใช้ตัวโหลด .env ที่คุณชอบ
npm start              # เปิด http://localhost:3000
```

## พฤติกรรมที่ควรรู้
- Super admin จัดการบัญชีจากปุ่ม **จัดการผู้ใช้** ได้: เพิ่มบัญชี เปลี่ยนชื่อ/บทบาท เปิดหรือปิดใช้งาน และรีเซ็ตรหัสผ่าน; ปิดใช้งานแทนการลบเพื่อเก็บประวัติ และต้องมี Super admin ที่เปิดใช้งานอย่างน้อยหนึ่งบัญชีเสมอ
- การรีเซ็ตรหัสผ่านหรือเปลี่ยนบทบาท/สถานะจะออกจากระบบทุกเซสชันเดิมของผู้ใช้นั้น ส่วนประวัติการจัดการบัญชีดูได้ในหน้าจัดการผู้ใช้
- **กันแก้ทับกัน**: ทุกสินค้ามีเลขเวอร์ชัน ถ้าสองคนแก้สินค้าเดียวกันพร้อมกัน คนที่บันทึกทีหลังจะได้ข้อความแจ้ง และหน้าจอโหลดข้อมูลล่าสุดให้ (การแก้ของคนนั้นต้องทำซ้ำ)
- สร้างและลบหมวดหมู่แยกจากสินค้าได้จากปุ่ม **จัดการหมวดหมู่** และเลือกใช้ภายหลังได้ โดยหมวดหมู่ตอนเพิ่มสินค้าไม่บังคับ; หมวดหมู่เดิมจะถูกนำเข้ารายการกลางอัตโนมัติ และลบได้เฉพาะหมวดหมู่ที่ยังไม่มีสินค้าใช้
- คลิกชื่อสินค้าในตารางเพื่อดูรายละเอียด จำนวน จุดสั่งซื้อ ที่เก็บ และรูปภาพ; กดรูปเพื่อเปิดดูรูปขนาดใหญ่ และแก้ไขสินค้าได้จากหน้ารายละเอียด
- หน้าเว็บดึงข้อมูลใหม่ทุก 15 วินาที (ข้ามเมื่อกำลังเปิดฟอร์ม/มีการแก้ค้างอยู่)
- ล็อกอินหมดอายุ 12 ชั่วโมง, จำกัดการเดารหัสผ่าน 8 ครั้ง/5 นาที/IP
- รูปสินค้าเก็บในฐานข้อมูล (ย่อเหลือด้านยาวไม่เกิน 900px ฝั่งเบราว์เซอร์)
- **สำรองข้อมูล**: เปิดการสำรองอัตโนมัติ (backup) ของผู้ให้บริการฐานข้อมูล และกดปุ่ม "สำรองเป็น JSON" เก็บไว้เป็นระยะ
- ไฟล์ JSON สำรองครอบคลุมข้อมูลสินค้าและประวัติคลังสินค้า แต่ไม่รวมบัญชีผู้ใช้หรือประวัติการจัดการบัญชี; ให้ใช้ database backup เพื่อสำรองข้อมูลเหล่านี้
- กู้คืนจาก JSON จะ **แทนที่ข้อมูลและประวัติทั้งหมด** บนเซิร์ฟเวอร์
- ระบบไม่จัดเก็บหรือแสดงราคาสินค้าอีกต่อไป การเริ่มระบบหลังอัปเดตจะลบคอลัมน์ราคาเดิมจากฐานข้อมูล และการกู้คืนไฟล์สำรองเก่าจะไม่นำราคากลับมา
